# RepoProof

把项目描述里的可核验声明，逐条连到公开 GitHub 仓库中的文件、依赖清单和许可证元数据。每条结论附固定提交的链接，并写明它支持什么、不支持什么。

在线使用：<https://repoproof-m4h0tvkp9cl.qoder.website>

无需登录，不上传文件，不读取私有仓库。

## 核验什么

- **R1 路径**：声明的文件或目录能否在固定提交中访问。404 只记为“公开证据不足”，不写成“文件不存在”。
- **R2 依赖清单**：`package.json`、`requirements.txt`、`pyproject.toml`、`go.mod` 等是否声明了该依赖；不证明依赖被实际调用。
- **R3 许可证**：GitHub 识别的 SPDX 标识。`null` / `NOASSERTION` 只记为“未识别出可用的 SPDX 许可证元数据”，不写成“无许可证”。
- **R4 目录清点**：按类别统计文件，用于发现材料入口；只说明是否存在，不评价内容。目录树被截断时整次清点记为“无法完成核验”。

## 四种状态

`元数据不一致 → 公开证据不足 → 无法完成核验 → 发现公开证据`

- 403 / 429 等取数失败记为“无法完成核验”，不算到项目头上。
- 提交时间不参与任何判定。
- 每张结果卡都同时写“支持什么”和“不支持什么”。

边界：只核对公开仓库中可访问的材料。公开证据不足，不代表项目没有实现；本工具不判断个人贡献或功能真实性。

## 本地运行

需要 Node.js 20 或更新版本。

```bash
npm start
```

打开 <http://localhost:4173>。

```bash
npm test
```

运行核心与应用测试（42 个用例）。

```bash
npm run build
```

生成静态产物到 `dist/`，可直接托管；不依赖后端。

## 目录结构

```
src/core      判定规则、状态、报告、URL 解析（不依赖 DOM 与网络）
src/app       用例、会话、示例快照、证据单导出
src/adapters  GitHub 读取网关与示例快照适配
public/       页面、样式与交互（原生 ES 模块，无构建框架）
scripts/      本地开发服务器与静态构建
tests/        核心与应用测试
submission/   参赛作品帖、演示脚本、真实案例与界面截图
```

页面是原生 ES 模块，没有打包器；`scripts/build-static.mjs` 会把 `public/` 与 `src/` 复制到 `dist/` 并改写引用。

## 部署

线上版本通过 Qoder Sites 发布。`.RepoProof.qoder.site` 是部署账号的本地绑定文件，已排除在仓库外；队友部署时需要用自己的账号重新发布。

## 协作

公开仓库，默认分支 `main`。写入权限需要在 Settings → Collaborators 邀请后获得。

仓库暂未添加开源许可证。
