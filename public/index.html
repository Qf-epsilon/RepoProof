粘贴一段简历里的项目描述，或直接输入公开仓库地址。系统把它拆成可核验声明，确认后逐条核对文件、依赖清单和许可证；每条结论都附固定提交的链接，并写明它支持什么、不支持什么。

判定状态

四态分开，失败原因可解释。

    案例库

    真实公开仓库的固定快照，打开即看结果，不发起网络请求。

    核验流程

    三步，核验对象都由你确认。

    1. 01
      读取仓库

      粘贴描述时先提取仓库地址；读取默认分支，并把证据固定到当前提交。

    2. 02
      确认对象

      自动提取的候选声明标记为“建议”，逐条确认或删除后才执行。

    3. 03
      逐条核验

      给出状态、证据链接和支持边界。

    适用范围

    只核对可机械核实的声明。

    声明 核验依据 边界
    使用了某框架或库 依赖清单里的声明 不能证明实际调用
    包含测试、CI、Docker 或文档 对应路径能否访问 不能证明质量或覆盖率
    采用某许可证 GitHub 识别的 SPDX 不能判断许可证是否适用
    性能、用户量、个人贡献 没有公开可复现材料 不在核验范围

    数据来源 GitHub REST API、依赖清单原文、SPDX 元数据。

    只读取公开仓库，不保存输入。公开证据不足，不代表项目没有实现，也不判断个人贡献。
